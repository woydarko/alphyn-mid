# Alphyn

![CI](https://github.com/woydarko/alphyn-mid/actions/workflows/ci.yml/badge.svg)

> A private AI portfolio vault on Midnight. You answer a few questions, an AI picks an allocation, and the chain never sees it.

## What this is

Most DeFi is fully public. If you build a good strategy, the moment it lands on-chain everyone can copy it, and the moment a vault rebalances, bots front-run the next move. The edge is gone the second it becomes visible.

Alphyn takes the opposite approach. Your allocation is generated by an AI from a short risk questionnaire, and it stays private. It lives as witness data in a Compact contract, so only you ever hold the actual weights. What goes on-chain is a commitment (a hash) plus aggregate performance. Every rebalance is proven, in zero knowledge, to have followed the exact allocation you committed to. Nobody can read your strategy, not other users, not an indexer, not even us, but anyone can verify the vault played by its own rules.

The leaderboard shows aggregate PnL only. You can follow another vault's direction off its track record without either side's strategy being exposed.

This is a rewrite of an earlier EVM/iExec version. The old design leaned on a trusted execution environment to hide the strategy. Here that trust assumption is gone and replaced with a zero-knowledge proof.

## Known limitation: the Preview v9 transition

Midway through this build, Preview and the browser wallets moved to the new v9 transaction format (ledger-v9, compact-runtime 0.18, "proof-versioned" transactions). This project runs on the stable v8 line, which is the newest one with a released Compact compiler: the public compiler tops out at 0.31.1 and emits v8 artifacts, so a v9 contract build is not yet possible with released tooling.

What this means in practice:

- The browser extensions auto-updated to v9, so a submit through them is rejected with a format error. The app detects this and explains it instead of failing silently.
- The node itself still accepts v8 transactions. So the project ships a local execution bridge: a small service that holds a headless operator wallet on the v8 line and executes every circuit call. With the bridge running, the whole product works live on Preview today, end to end, from the same UI. This mirrors the original Alphyn architecture, where a backend runner executed on-chain while the frontend stayed pure UI.
- When Midnight ships the v9 compiler, this repo migrates by bumping versions and recompiling, and the extension path takes over again with no design changes.

Run the bridge (proof server 8.0.3 on :6300, seed in `deploy/.env`):

```bash
cd deploy
MIDNIGHT_NETWORK=preview npm run bridge
```

The app auto-detects it at `localhost:6363` and shows a "Local executor active" banner. Verified live through the UI: mint tx `00ca0c00b277…`, rebalance tx `00fb8600685a…`, both visible in the on-chain leaderboard.

## Epochs run automatically (the keeper)

Like the original Alphyn, epochs are not manual. The bridge doubles as a **keeper**: a background loop that runs one rebalance per active vault on a fixed cadence, using real price returns as the oracle. The browser just reflects it — the vault page shows "Keeper is running epochs automatically" and the chart grows on its own.

The difference from the old design is where trust sits. The original keeper ran inside a server-side TEE that held every user's strategy. Here the keeper is the operator wallet on the user's own machine, and the private allocation witnesses live next to it in `bridge-vaults.json`. Only the party that already owns the secret runs the proof; nothing private is handed to a remote operator, and on-chain only the commitment and aggregates are ever public. Cadence is `KEEPER_INTERVAL_SECONDS` (default 60 for demos). A manual "Run epoch" button is still there to trigger one on demand.

## Privacy Model

- **Public** (on-chain, anyone can read): a hash commitment to the allocation, a coarse category label (conservative / balanced / aggressive), the asset count, epoch count, cumulative gain and loss totals, and follower counts.
- **Private** (witness data, never leaves your machine): the actual per-asset weights, your vault secret, the balance, and the blinding nonce behind the commitment.
- **Proved without revealing**: that each rebalance used the same allocation you committed to at the start. The circuit recomputes the commitment from your private weights and checks it against the stored one. If they do not match, the proof fails.

Full breakdown of what an observer can and cannot learn is in [docs/PRIVACY.md](docs/PRIVACY.md).

## Tech Stack

- Midnight network, Compact language, ZK circuits
- midnight-js SDK and the DApp connector (works with 1AM and Lace wallets)
- Contract tests with Vitest against the Compact runtime
- React and Vite for the console (the wallet-driven app)
- Next.js for the marketing site
- OpenRouter for AI strategy generation, CoinGecko for the price feed

## Repo layout

- `contract/` - the Compact contract, its tests, and the compiled output. Start here.
- `console/` - the app you actually use. Connect a wallet, deploy or join a contract, create a vault, rebalance, follow, read the leaderboard.
- `services/` - strategy generation, price feed, the epoch keeper, and off-chain analytics (net PnL, Sharpe, drawdown).
- `deploy/` - a small headless CLI that deploys and drives the contract from a seed.
- `frontend/` - the Next.js landing page. Its "Launch App" button opens the console.

## Prerequisites

- Node 22 (the deploy CLI and contract tests) and Node 24 (the console build)
- Docker, for the proof server
- The Compact compiler
- A Midnight wallet (1AM or Lace) set to Preview, with test funds from the faucet

On Windows, run the toolchain inside WSL2. The compiler binary name `compact` clashes with the built-in Windows `compact.exe`, so WSL keeps things clean.

## Setup and run locally

Install the Compact toolchain:

```bash
curl --proto '=https' --tlsv1.2 -LsSf \
  https://github.com/midnightntwrk/compact/releases/latest/download/compact-installer.sh | sh
source ~/.bashrc
compact update
```

Start the proof server:

```bash
docker run -p 6300:6300 midnightntwrk/proof-server:8.1.0 -- midnight-proof-server -v
```

Compile the contract and run its tests:

```bash
cd contract
npm install
npm run compile      # writes src/managed/alphyn (circuits, keys, bindings)
npx vitest run       # 9 tests
```

Run the console (the app):

```bash
cd console
npm install --legacy-peer-deps
bash build-contract.sh   # compiles the contract into the console and stages ZK assets
npm run dev              # opens on http://localhost:5173
```

Open the console, connect your wallet on Preview, and the deployed contract address is already filled in. From there you can create a vault, run a rebalance, and read the leaderboard.

## Run tests

```bash
cd contract && npx vitest run     # contract circuits (9 tests)
cd services && npx vitest run     # strategy, price feed, keeper, analytics (15 tests)
```

## CI/CD

The workflow at `.github/workflows/ci.yml` runs on every push and pull request. It installs the Compact toolchain, compiles the contract, checks that the `managed/` output exists, runs the contract tests, and builds the frontend and services. The badge at the top of this file reflects the latest run.
